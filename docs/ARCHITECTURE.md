# 模块设计

## 依赖方向

```text
                       main.js
                          │
        ┌─────────────┬───┴───────┬─────────────┐
        ▼             ▼           ▼             ▼
       UI           core        combat        world
  HUD / Hotbar    Teleport     CombatEngine    World
  Dialogs / Map  Settings      job plugins     │
                                  │           ├─ scenes
                               action data    ├─ actors / assets
                                              ├─ entities
                                              ├─ input
                                              ├─ effects
                                              └─ renderer
```

`combat` 不导入 Three.js、DOM 或 UI。`world` 不计算威力、资源、技能复唱。UI 读取快照，通过动作 ID 请求施放，不自行判定连招。主入口将成功的技能事件交给视觉、音效和位移模块。

地图读取场景实际路径数据和实体位置。传送控制器只管理目的地、状态、读条和完成/取消回调，不负责构建场景。NPC 对话由交互回调打开，实体本身不操作界面。

## 职业

`combat/registry.js` 保存职业插件。插件负责该职业的初始状态、动态技能转换、使用条件、时间变化和施放后效果。共有引擎负责：

- 公共冷却、独立冷却、充能及动作僵直；
- 魔力、增益状态、持续伤害、技能队列和读条；
- 目标、移动、距离等通用条件；
- 统一事件、日志和统计快照。

新增职业的工作顺序：

1. 添加职业元数据及资源量谱声明；提供稳定的英文 ID、中文显示名和主题色。
2. 添加动作声明：名称、类型、威力、读条、复唱、范围、消耗和效果键。
3. 在 `combat/jobs/` 添加独立插件，实现注册表所需接口；不要把新职业判断散布到 UI。
4. 在 `combat/index.js` 装配注册。UI 从 `JOBS` 和 `getActions()` 自动生成职业按钮、量谱和技能栏。
5. 在外观注册入口添加角色武器/服装；没有专用外观时可使用通用角色。
6. 在 `scripts/verify.mjs` 加入有意义的资源循环验证。

动态技能保持原槽位和动作 ID，由职业插件改变显示名、效果及条件。例如同一按键可随着魂衣状态变成对应连段技能。不要让界面按显示名称推断战斗规则。

技能执行边界应明确：引擎成功后发出 `hit`、`heal`、`buff`、`cast`、`error`、`move` 等事件。消耗、增益和动作转换只发生在战斗引擎内；移动事件由 World 应用空间变化。

## 场景

场景元数据保存在 `world/scenes.js`，构建器位于 `world/scenes/`。每个构建器负责地面、道路、装饰、障碍、出生点和实体布置；`World` 负责公共相机、输入、目标、更新和资源释放。

增加新地图时同时注册元数据和构建器：

- 使用稳定 ID，例如 `uldah`；
- 元数据提供 `name/en/region/description/accent`；
- 构建器返回或填写场景空间数据、出生点、碰撞范围、可供地图显示的道路矩形；
- 通过实体注册器放置 NPC、木人或怪物；
- 执行切换与离开后的资源释放检查。

传送目的地源于同一元数据数组，禁止另维护一份下拉菜单地图列表。

## NPC 和怪物

实体注册器维护 `id`、`type`、`name`、`object`、坐标以及可选的等级、生命、朝向和对话。Three.js 模型子节点应继承实体 ID，便于射线选择。NPC 使用对话回调；木人和怪物使用战斗目标回调。

新增 NPC 可复用角色构建器，注册 `type: 'npc'` 和对话文本。为怪物添加行为时，把 AI 更新放在独立的行为模块，通过实体状态与 World 交互，不让 AI 直接访问技能栏 DOM。

当前木人为无限练习目标。将来加入可击杀怪物时，适合在独立 Encounter/TargetState 中接收已结算伤害、改变目标生命并发出死亡事件；不要把装备伤害公式放进 Three.js Mesh。

## 表现层

`assets.js` 提供可复用材质、程序化纹理和建筑素材；`actors.js` 管理角色及武器；`effects.js` 接受引擎事件。可以按事件的动作 ID 添加专用效果，也可以使用职业主题作为后备效果。

图形质量只影响渲染分辨率、阴影等选项，不改变引擎时间或战斗数值。设置保存于浏览器本地存储，练习状态保存在当前运行实例中。

持续地面效果由 `EffectSystem` 管理半径、存续时间与几何体；World 只返回玩家当前所在区域的 ID。职业插件据此判断加速等效果是否生效，场景层不识别职业技能规则。海都通过可行走矩形/圆形集合限制水面通行，位移技能与普通移动共用导航判定。

`core/TrainingDirector.js` 提供默认关闭的非致命受伤节拍，用于验证治疗技能。职业减伤和治疗加成分别通过 `modifyIncomingDamage`、`modifyHealing` 钩子进入通用引擎。

`ui/Hud.js` 只渲染状态。`ui/Hotbar.js` 负责动作分页、冷却显示、触发提示和按键映射。`ui/Dialogs.js` 负责传送、技能书、设置、地图、对话与帮助。样式按基础、HUD、窗口和响应式拆分。

## 验证与调试

`npm run verify` 检查核心职业循环和规则边界，`npm run build` 验证模块打包。浏览器调试入口为：

```js
window.__APP__.combat.getState()
window.__APP__.combat.getActions()
window.__APP__.world.getContext()
window.__APP__.world.getInfo()
```

这是开发调试入口，生产玩法通过正常技能栏和快捷键完成。构建不依赖测试框架，不为简单界面样式建立镜像测试。
