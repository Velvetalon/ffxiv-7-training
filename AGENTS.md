# Project workflow

- The coordinating agent must not read, load, display, or decode images. Pass image paths to a subagent for any image operation, including screenshots and visual verification. Subagents return text findings and artifact paths only, never images or base64.
- Keep runtime asset references relative. Verify the built application under `/ff14-web/`, including redirecting `/ff14-web` to its trailing-slash form.
- `site/` is the committed, ready-to-run build. After runtime changes, rebuild it and verify it without `node_modules` or an installed game client before pushing.
- `public/extracted/world/` contains versioned full-world packages; `bundled/` retains the initial two cities. Keep raw client files, intermediate exports, old staging releases, credentials and `work/` out of Git.
- The full world catalog has 65 scenes and the source-derived graph currently has 145 directed connections. Verify full catalog coverage and endpoint provenance; do not use a partial-map check to claim world completion.
- Use the existing combat, camera and map checks. Do not add redundant tests for trivial changes.
- Default to `docs/FAST-VALIDATION.md` and `npm run validate-fast`. This is a personal demo, not a commercial QA program. This policy supersedes the former impact/full-regression defaults in `docs/REGRESSION-VALIDATION-STRATEGY.md`.
- Use only two default layers: one lightweight automated all-map smoke pass, then the fixed four representative maps in `config/fast-validation.json`. Smoke stops at basic renderable/core-ready state; it does not wait for full background streaming or all full-resolution textures.
- Normally run a complete smoke pass at most once per development phase. After a passing pass, non-core edits do not trigger another full pass. Recheck only failed/timeout maps and, when relevant, the fixed representatives. Repeat all-map smoke only for a real global failure or changes to loader/renderer/parser/bundle/manifest/global shader or other clearly global core behavior.
- Let native scripts process maps and filter results. The main agent reads only compressed totals, failures, timeouts, serious regressions and relevant errors. Do not inspect normal map logs, request traces, resource logs, or hundreds of PASS records; do not use model turns to poll individual maps.
- Representative observation checks appearance, movement, camera, obvious missing materials/geometry and the changed feature. Do not randomly expand beyond the fixed sample unless the change explicitly affects another map. Automated representative checks are assistance, not proof that visual or task-specific observation occurred.
- No default repeated full regressions, per-map screenshots/image diffs, stress tests, full benchmarks, browser matrices or exhaustive edge tests. Existing heavy tools remain opt-in for tasks that require them. Image observations still belong to a subagent, never the coordinator.
- Record total validation time, mean smoke time, timeouts and exception count. Simplify a slow validation tool instead of adding checks. Unknown rare edge cases, minor visual artifacts and noncritical delayed assets do not block completion; crashes, widespread load failure, missing core resources, broken changed functionality and severe slowdown do.
- Server-specific connection information belongs in ignored `work/deployment/`. Preserve other applications on the server and keep a previous deployment for rollback.
